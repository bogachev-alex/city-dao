## Bug 1: Amount display — 0.15 SOL shown as 150 000 000 ₸

### Root cause
- Admin form has `amount_usdc: 120000000` (test data = 120M tenge)
- This tenge value is sent to `createContract()` as `totalAmount` and stored in DB
- The contractor dashboard displays `formatTengeWithCrypto(totalAmount)` which interprets the value as tenge
- Meanwhile, the on-chain amount is correctly converted via `tengeToLamports()` and capped
- **But**: the DB stores the original 120M tenge, so the dashboard always shows 120M ₸

### Fix
The DB should store the **actual on-chain amount** (in lamports), not the form's tenge value. Or better: store both the original tenge amount AND the on-chain lamports amount.

Actually the real issue is simpler: the form field `amount_usdc` is confusingly named but stores tenge. When a user enters 0.15 SOL worth of contracts, they're probably entering a much smaller tenge amount. But the test data fills 120,000,000 which is displayed correctly as 120M ₸.

**Wait** — the user says they register contracts at "0.15 SOL". This means they manually enter a small amount. Let me re-check...

The on-chain amount is calculated as:
```
fullLamports = tengeToLamports(Number(form.amount_usdc))  // tenge → lamports
onChainAmount = Math.max(minTotal, Math.min(fullLamports, maxTotalForEscrow))
```

If user enters e.g. 12000 (tenge):
- fullLamports = tengeToLamports(12000) = (12000/80000)*1B = 150,000,000 lamports = 0.15 SOL ✓
- DB stores totalAmount = 12000 (the form value)
- Dashboard shows `formatTengeWithCrypto(12000)` = "12 000 ₸ (0.2 SOL / 24 USDT)" — that seems correct?

But the user says 0.15 SOL shows as 150,000,000 ₸. This would happen if:
- User enters 12000 in the form
- `tengeToLamports(12000)` = 150,000,000 lamports 
- `onChainAmount` = 150,000,000 (sent on-chain)
- **BUT** `totalAmount: Number(form.amount_usdc)` = 12000 sent to DB
- So DB has 12000, not 150M

Unless... the user enters the amount differently. Or maybe the `amount_usdc` field label is confusing and users enter lamports/SOL directly.

**Actually**: Looking at the form, the field is labeled with amount label and placeholder "100000". The hint shows escrow 20% in ₸ and on-chain in SOL. So users enter tenge.

The real issue might be in `applyOnChainOverlay` — when the on-chain data overlays DB data, it replaces `amount_usdc` with the on-chain amount (which is in lamports!). Look at lines 85, 165:
```js
amount_usdc: live.amount_usdc ?? c.amount_usdc,
```

If `live.amount_usdc` is the on-chain `total_amount` in lamports (150,000,000), and `formatTengeWithCrypto` treats it as tenge, that's the bug!

### Actual Fix
In `applyOnChainOverlay`, the on-chain `amount_usdc` is in lamports but gets treated as tenge by `formatTengeWithCrypto`. Need to convert on-chain lamports to tenge before overlaying.

File: `app/[locale]/contracts/page.tsx` lines ~85 and ~165
Change: `amount_usdc: live.amount_usdc ?? c.amount_usdc` → convert lamports to tenge: `lamportsToTenge(live.amount_usdc) ?? c.amount_usdc`

Also in the contractor dashboard (`app/[locale]/contractor/page.tsx`), same issue if it overlays on-chain data.

## Bug 2: Search by contractor name doesn't find contracts

### Root cause
- The search at line 278 checks `c.contractor.toLowerCase().includes(q)`
- `c.contractor` comes from `normalizeContract()` line 259: `c.contractor?.name || c.contractor || ''`
- When the API returns `{ contractor: { id, name } }`, this works
- But when `contractor` is null (no linked contractor), search fails silently

### Fix
The contracts page search already works for contractor name matching. The issue is likely that:
1. The newly created contracts have `contractorId` properly set, so `contractor.name` is available
2. But the `contractorScope: 'mine'` filter (line 288) compares `c.contractor` with `user.name` — these need to match exactly

Let me verify the API returns contractor data for the user's contracts...

Actually, looking at the `GET /api/contracts` endpoint (line 37):
```js
contractor: { select: { id: true, name: true, rating: true } },
```
This returns the contractor relation. So `normalizeContract` should extract `contractor.name`.

The real issue: when user registers as contractor "Замир Безгоев" and creates contracts assigned to this contractor from the admin panel (via the select dropdown), the contractor name in the DB should match. But the search might be case-sensitive or have whitespace issues.

### Fix
Ensure the search is robust — it already uses `.toLowerCase()` and `.includes()`. The issue might be that:
1. The contractor was created without a wallet (from seed or admin form typing)
2. The contractor "Замир Безгоев" from `/register-contractor` has a wallet but different DB record than the one selected in admin dropdown

We need to ensure the contractor dropdown in admin actually links to the wallet-registered contractor.
